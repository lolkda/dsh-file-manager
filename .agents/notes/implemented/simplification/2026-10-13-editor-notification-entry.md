# Agent Note: 编辑窗口移除重复通知入口

Status: implemented

## Problem

文件编辑/预览窗口在保存按钮旁重复展示全文件管理器的“通知”，容易让人误解为当前文件专属操作。用户明确要求使用 Agent Team 移除，由 Lead 审查逐文件改动与质量。

## Decision

- 通知入口仅在文件管理器主界面右上角保留；编辑/预览窗口不渲染通知按钮或隐藏占位，任务窗口维持无重复入口。
- 只删除查看器顶部的入口实例，不修改通知 store、事件发布、可访问 live region、保存/草稿状态、返回、关闭与冲突确认；不新增反馈机制或发布/安装流程。
- 编辑期间的结果仍进入会话通知记录。需要查看详情时返回列表再打开通知；返回不丢失草稿，再次进入继续编辑。

## Ownership and history audit

- [会话内通知中心](../feature/2026-10-12-notification-center.md)：部分取代其“查看器保留入口”的决定；保留原方便编辑时查看结果的理由及其余通知状态/生命周期规则，互链而非归档。
- [直接文件编辑](../feature/2026-10-10-direct-file-editor.md)：相关但不取代；保存、草稿和冲突语义不变。
- [精简文件导航](2026-10-10-compact-file-actions.md)、[固定文件系统根](2026-10-12-fixed-filesystem-root.md)、[宿主路径剪贴板](../bug-fix/2026-10-10-host-path-clipboard.md)、[复制路径](../feature/2026-10-09-copy-paths.md)：仅共享通知话题，没有重叠决定，不改写。
- 本次基线存于忽略目录 artifacts/remove-editor-notification-2026-10-13；已有大量未提交改动，评审只比较本次快照增量，不回滚或认领旧改动。实现成员只写 panel，测试成员只写通知回归，Lead 维护规格/笔记并统一构建，审查成员只读。

## Alternatives considered

- 保留编辑器内通知入口：编辑时不用返回列表就能查看保存或后台任务结果；但它是全局记录而非文件动作，用户要求简化编辑窗口，因此移除这个重复入口。
- 仅用 CSS 隐藏：改动表面最小，但仍保留冗余组件和潜在可访问/布局问题，不如直接移除渲染实例清晰。

- 旧构建上的新单入口用例按预期失败：2 个按钮而非 1 个。源码增量经实现成员和 Lead 核对只有删除一行 viewer 的 notificationEntry。

## Consequences

主界面拥有唯一通知入口，避免将全管理器记录误认为当前文件动作；代价是编辑期间查看通知详情多一次返回操作。普通错误依旧记录在通知中，本次不声称新增编辑器内错误提示。组件测试不等于在线 GUI 已更新；Chrome DevTools 连接失败，不自动安装、重启或宣称完成真实浏览器验收。
