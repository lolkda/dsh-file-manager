# Agent Note: 精简文件导航与轻量保存入口

Status: implemented

## Problem

用户截图中的文件窗口保存按钮以 primary 实心块展示，与同一标题栏的返回和关闭控件不协调；用户同时要求删除操作栏的“上一级”入口及逻辑。文件主标题下的“实时监测中”独占一行并持续挤占列表高度，用户要求连同该行占位一起去掉。

## Decision

- 保存沿用宿主 ghost 小按钮，与返回和关闭入口一致；不自画图标、不改全局主题。无修改、保存中、只读与失效文件的既有门禁不变，保留保存中反馈、快捷键和关闭脏文件确认。
- 文件操作栏仅保留新建、上传、更多。空根目录位置入口由[固定文件系统根](2026-10-12-fixed-filesystem-root.md)删除。不存在上一级按钮、专用父路径计算与翻译键；面包屑现有根/祖先导航继续有效，忙碌时仍禁用，不删除通用目录导航。
- 桌面“更多”菜单与同栏其他分组使用左边缘锚定；删除上一级后触发器左移，原专用右锚定会使菜单左溢出约10px。手机继续使用底部工具栏范围内的右侧锚定，不改变其他菜单。
- 文件主标题和路径栏之间不渲染任何监测状态行，也不保留其 padding、空节点或隐藏占位；移除仅供展示的 `watchStatus` state 和五个 `watch.*` 翻译键。`startWatch` 继续订阅和刷新目录、保护脏草稿、重连与清理，状态回调不再触发渲染，错误仍进入已有通知中心；不修改 Host、SSE 协议或监测模块接口。只读降级提示不属于监测状态，继续保留。
- 直接勾选、底部选择计数、任务行为、Host 与协议不变。复制能力修复由[宿主路径剪贴板](../bug-fix/2026-10-10-host-path-clipboard.md)单独记录。

- [直接文件编辑](../feature/2026-10-10-direct-file-editor.md)：保存动作与单标题栏契约保留，本次仅复用不同现成视觉 variant，不替代该决定。
- [响应式查看器](../feature/2026-10-09-responsive-file-viewer.md)：面包屑、覆盖层和三端布局继续有效。

## Alternatives considered

- 保留 primary 保存：主操作更醒目；但用户明确指出块状按钮突兀，且标题栏保持轻量比持续强调未启用的保存更重要，使用现成 ghost 而非自定义颜色。
- 仅隐藏“上一级”：改动更小且可恢复；但用户要求删除逻辑，而面包屑已提供祖先导航，保留不可达分支没有收益。
- 仅隐藏监测文字或用 CSS 保留状态行：改动最小且随时能恢复展示；但仍留下无意义占位或失效的显示状态，无法同时满足精简布局，因此删除整行及专用状态，不关闭实际监测。

## Consequences

ghost 降低保存的视觉权重，未保存标记、可用状态和快捷键继续存在。祖先导航依赖面包屑，深路径使用已有横向滚动，不重新引入上一级按钮。工具栏继续按内容宽度布局，增删按钮后须检查菜单锚定而非只看按钮本身。

浏览器夹具使用内存保存传输，不操作用户文件；真正文件保存仍由完整Host回归验证。未经认证GUI返回401，独立夹具不代表运行中页面已激活；物理触控、软键盘与实际安装重启分别报告。

移除监测状态行后，常规连接、轮询、不可用与断线状态不再直接展示，超过 128 个监测目标的既有拒绝启动门禁也不再显示专用提示；目标限制本身不变，手动刷新继续可用。保留既有 `onError` 通知不意味着每次断线都会发通知，常规重连不生成新通知事件。
