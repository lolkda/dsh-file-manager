# Agent Note: 文件标签与编辑窗口分离关闭范围

Status: implemented

## Problem

文件窗口右上角 X 绑定 closeDocument(active.id)，多文件时只移除当前文件而留在窗口中；文档导航没有单独的关闭按钮。用户要求标签各有 X，窗口 X 关闭整个编辑页面，两者不能共用文档销毁语义。

## Decision

- 所有已打开文件（包括单文件）在顶部仅显示一次文件名及独立 X。文件切换按钮与关闭按钮为兄弟节点，禁止嵌套按钮；关闭按钮的可访问名称包括路径，明确目标。
- 标签 X 只关闭对应文档，不先激活非当前文档。干净文件直接关闭；脏文件复用保存/放弃/取消确认；保存中禁用该文件的关闭。关闭非活动标签保留活动文档，关闭活动标签复用 store 的后继选择，关闭最后一份文档回到列表。
- 窗口右上角 X 使用独立 close-viewer 动作和“关闭编辑器”名称，只隐藏编辑窗口，保留文档、草稿和同一编辑器实例；保存中也可隐藏，不取消保存。再次从已打开文档入口恢复。
- 标签关闭前，若焦点确在该关闭按钮中，先移到稳定存在的窗口 X，再关闭或打开脏文档确认。避免标签删除把 activeElement 留在 body，也为宿主确认层提供不会被删除的恢复焦点目标；不改通用覆盖层焦点机制。
- 窗口 X 在加载/失败状态下清除当前读取尝试并递增 generation，使迟到响应既不新增文档也不重新打开窗口。返回列表/Escape/背景点击的既有非销毁语义保持不变。
- 保留公开宿主 Button 与关闭图标；保持局部横向滚动、窄屏控件可达；不改 Host、HTTP、DocumentStore 生命周期、依赖或任务/通知行为。

## Existing decision audit

检索 .agents/notes 的现有活跃记录（当前无 rejected 或其他 proposed）：

- [直接编辑](../../implemented/feature/2026-10-10-direct-file-editor.md)：部分取代单文件不设标签和窗口 X 关闭当前文档的决定；直接可写、原生换行、宿主素材和保留挂载理由仍有效，互链而不归档。
- [响应式查看器](../../implemented/feature/2026-10-09-responsive-file-viewer.md)：延续隐藏保留编辑器、关闭最后文档返列表、焦点及确认层约束，不取代。
- [通知入口精简](../../implemented/simplification/2026-10-13-editor-notification-entry.md)：无关；保留编辑器内没有通知入口。
- 其余通知中心、复制路径、统一选择、精简操作和固定根笔记只共享关闭/窗口关键词，不改变其决定。

## Alternatives considered

- 窗口 X 批量关闭所有文档：可释放编辑状态，字面上“全关”直接，但会新增批量脏文件确认和部分关闭状态机；用户要求关闭编辑页面，不要求丢弃工作，现有隐藏/恢复契约更安全且一致，因此不批量销毁。
- 单文件仍仅标题、不提供文件 X：保留原有最简标题，但窗口 X 改成隐藏后会失去关闭最后一份文档的明确入口；采用单份也有文件关闭按钮，文件名仍只展示一次。
- 在通用 Overlay 中监听焦点丢失并自动抓回：可覆盖更多移除控件的场景，但扩大所有覆盖层的行为范围，可能抢走子确认层焦点；本次仅已知标签删除导致问题，因此在文档关闭入口转移到稳定控件。同行切换按钮也随整行删除，不能作为后继目标。

## Consequences

标签关闭和窗口关闭不再共享销毁语义。用户可关闭任意一份文档，也可退出窗口而保留全部草稿；代价是标签 X 占用更多宽度，需要局部横向滚动，且关闭标签时焦点转到稳定窗口按钮而非已销毁标签。

窗口隐藏仍占有文档内存，与原有返回列表契约一致。真实浏览器夹具使用构建产物与宿主 UI，不等同已认证 GUI 激活。部署使用 DSH 官方插件命令安装已测试的打包快照，安装前备份原包和 profile 元数据，安装后核对包文件与其他 profile 配置；运行中 JavaScript 模块仍须重启加载，安装完成不能作为已激活证明。具体实例的安装校验、GUI 认证状态及重启结果单独报告，不写成产品契约。
