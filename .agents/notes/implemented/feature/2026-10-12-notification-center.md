# Agent Note: 文件管理器会话内通知中心

Status: implemented

## Problem

“已复制”等结果横幅插入文件列表上方，持续占用列表高度；复制路径、文件任务剪贴板、操作结果与普通错误分散在多个组件，既没有统一入口也没有可回看的事件历史。用户选择只改文件管理器，并确认采用桌面侧抽屉/手机全屏、仅当前页面会话保留、最近 100 条；不改整个 DSH，不新增持久化。

## Decision

查看器重复入口的决定由[编辑窗口移除重复通知入口](../simplification/2026-10-13-editor-notification-entry.md)部分取代；现在仅主界面保留入口。下述通知生命周期、事件/业务状态隔离、抽屉及确认规则继续有效。原查看器入口旨在编辑时直接查看操作结果，其取舍在新笔记中保留。

- 原入口布局为文件列表与查看器右上角均保留通知入口与未读数（查看器入口现由上面的精简决定移除）；打开右侧抽屉，窄屏占满面板。任务面板顶部不重复显示通知入口，其“关闭”按钮仅收起任务面板，不取消任务、不清除历史，也不改变通知或文档状态。按时间倒序显示成功、信息、警告、错误，支持逐条移除、全部清空和已读。查看通知不改变当前目录/文档/勾选，关闭恢复原界面，不自动弹出横幅或抢焦点。
- 通知 store 属于插件 apply 生命周期而非 Panel 生命周期，切换面板仍保留，插件卸载释放订阅并丢弃，刷新页面自然清空。无 localStorage/sessionStorage/Host 持久化；最多 100 条，去重 bookkeeping 也有界。
- 明确通知是“事件展示”，不拥有文件或任务状态。清除通知不能清空文件任务剪贴板、取消任务、关闭任务历史、丢弃草稿或取消待插入引用。可操作通知使用显式类型化导航数据，不能存 React 节点、任意回调或可执行 Host 请求；危险操作仍走原确认门禁。
- 接入路径复制成功/失败、文件复制/剪切摘要、目录上传后备提示、删除/新建/重命名/保存等操作结果、普通错误，以及任务/传输的终态转换。持续轮询、重复 SSE 与视图重挂载不能刷屏；首次加载历史终态不当成新完成事件，用户当次直接得到的终态结果不漏报。
- 移除文件列表上方的对应通知横幅。复制失败的完整手动复制文本放在通知详情，不截断、不给错误的成功反馈；目录状态、不可寻址条目、实时监听状态和任务详情属于当前业务状态，不伪装成事件历史。实时监听状态行的展示由[精简文件导航](../simplification/2026-10-10-compact-file-actions.md)部分取代：删除显示与占位，但保留后台监听及原错误通知，不将常规状态变更搬入通知历史。只读降级需通知并保留紧凑的状态标识/写入禁用，不能只靠用户打开通知才知道不可写。
- 删除确认、未保存退出确认、冲突解决与表单校验继续在现场。待处理引用的操作控件移入任务详情并由通知导航过去，不因清通知丢失处理入口。固定根访问失败作为通知报告，不提供位置管理或恢复入口，见[固定文件系统根](../simplification/2026-10-12-fixed-filesystem-root.md)。

## Client contract

新增 notifications.ts 的纯 store：NotificationInput { level: 'success'|'info'|'warning'|'error', title: string, message?: string, details?: readonly string[], action?: NotificationAction, dedupeKey?: string, code?: string }；NotificationAction 为 {kind:'surface',surface:'tasks'|'viewer'} 或 {kind:'manual-copy',text:string}。记录额外带 id、createdAt、read；getSnapshot 返回 entries 与 unreadCount，publish/markRead/remove/clear/subscribe/dispose 不操作业务 store。展示字符串在事件发生时由现有翻译生成，不新增线上协议或依赖。

Panel 通过新增 notifications prop 使用 root-owned store；FileSection 同样显式注入。索引入口负责创建和释放；任务/引用观察器属于插件根生命周期，先区分初始历史与真实状态变化，再发布去重事件。普通点击产生的新事件不被全局错误码去重误吞；watch/SSE 重复状态以来源键去重。

## Ownership and history audit

- [固定文件系统根](../simplification/2026-10-12-fixed-filesystem-root.md)取代旧动态根入口恢复：删除 roots 通知导航与恢复提示，其余事件展示/业务状态隔离不变。旧恢复决定在[归档记录](../../archived/bug-fix/2026-10-12-root-reauthorization.md)保留。
- [原复制路径](../../implemented/feature/2026-10-09-copy-paths.md)、[宿主剪贴板](../../implemented/bug-fix/2026-10-10-host-path-clipboard.md)：部分重叠，完整文本手动兜底与输入隔离保持，只有提示位置改为通知详情，双向链接。
- [统一勾选](../../implemented/simplification/2026-10-10-unified-file-selection.md)关于“不额外占列表高度”的决定继续成立，本篇延伸至操作提示，不替代选择语义。
- core 队员只写 store、事件观察器、index、path-copy、browser 与纯 store 测试；UI 队员只写 panel、新通知视图、i18n/styles；QA 独占组件测试与必要 harness；Lead 写笔记/规格、跨模块 review 与统一构建。不得修改 Host/contracts 或已有授权规则。

## Alternatives considered

- 在任务面板保留重复通知入口：任务运行时可直接查看结果，减少一次返回操作；但用户要求精简任务顶部，因此当时只移除此入口，通知中心及文件列表/查看器入口保留。查看器入口随后由上述精简决定移除，通知中心本身继续保留。
- 只把横幅换成自动消失 toast：改动最小且能及时反馈，但没有用户要求的统一通知历史，批量操作仍打断视觉，不采用。
- 接入整个 DSH 全局通知：长期可供多个插件复用，但用户明确限定只做文件管理器，宿主级扩展超出本次范围。
- 持久化通知历史：刷新后还能追踪结果，但增加账号/工作区隔离、失效操作与容量迁移约束，用户选择仅页面会话内保留。
- 把确认和业务状态也全部搬进通知：列表最简，但会隐藏必需的确认/只读约束，并使清通知改变处理入口，因此区分事件提示与业务状态。

## Review and verification

Lead 逐项关闭了以下问题：异步导入历史终态被误报；大于 1000 条历史扫描淘汰尚未检查的活跃任务；未见 queued 帧的新重试代次漏报；action 展开复制把回调带入历史；Panel 卸载后持久失败丢通知；普通错误源只改旧 error 状态却没有通知；live region 位于 inert 区域或移除最新条目时重播旧消息；未读数无可访问名称；无反馈的手动复制重试按钮；待处理引用清通知后失去入口。

状态观察以每轮有界快照查询上一状态，优先保留活跃记录；初次见到终态静默，用户当前 mutation 的直接终态显式 reportTerminal，二者共用事件键。历史条目 100、去重键 400、观察器记录有界；移除/清空保留同次事件键，不因 SSE 重放复活。新的人工动作无键或新键，重试含新 revision。publish 去重返回已知事件 ID，不保证对应条目仍在展示列表。action/message/details/code 经白名单与字符串校验，不保存回调，不截断手动复制文本。

实际执行：

- `npm run check` 通过：类型检查、Client/Host 构建与 20 个产物语法检查；最终 Client 为 1,348,885 字节。
- UID/GID 1000 下完整 `npm test`：921/921 通过，0 失败、0 取消、0 跳过；通知工作前基线为 860 项。
- 新增纯 store/事件测试 31 项、组件测试 27 项、真实 DOM 测试 3 项；这些均包含在 921 中，不重复累计。17 个 client-harness 使用方共 273 项通过。
- 真实 SSE 数据帧注入 → Panel 按 id 向真实 Host 重取 → 状态观察器 → 恰好一次通知的组件链路已覆盖，包含相同 seq 重放与同状态新 seq。当前 mutation 的直接终态用真实 task engine 结果控制 HTTP 回包时序，确保不是只调用 helper 的假接线验证。
- 覆盖容量/未读/去重/清除隔离、手动文本保真、独立抽屉焦点/Escape、面板重挂载与插件重建、持久失败跨卸载、原安全确认与只读门禁。Host、contracts、依赖清单相对此任务基线保持字节一致。
- 旧提示测试迁移到通知 code/level/动作断言；R18 含 LF 文件名仍不可寻址，全文保真通过可寻址长中文名与纯文本边界验证。共享 data 标记同时出现在行和按钮，唯一性按元素类型与可交互层断言，不用 `>=1` 掩盖重复 UI。

## Consequences

通知不主动展开，结果通过未读数和非视觉 aria-live 反馈，用户需要主动查看详情。最多 100 条是条目上限；手动复制文本必须保真，不能用静默截断换内存上限。历史事件沿用发生时语言。打开通知标读但不改变当前目录、选择或文档；清除历史不改变业务处理能力。

真实 GUI 的像素布局、真实键盘/IME、真实浏览器网络与屏幕阅读器播报尚未验收：现有 Chrome DevTools 不可连接，GUI 匿名访问 401。组件数据帧测试不是完整浏览器/网络验收；连续同标题通知的读屏重复播报没有物理设备验证。本次不自动重启 DSH、不修改在线根授权存储，构建产物不等于运行实例已加载。

本次原始基线、日志与增量报告位于本地忽略目录 artifacts/notifications-2026-10-12；统计只包含通知中心工作，不混入先前根恢复或其他未提交改动。
