# Agent Note: 响应式覆盖式文件查看器

Status: implemented

## Problem

旧桌面布局把根入口、目录列表、文本编辑器和任务区固定分配空间；窄屏只是纵向堆叠，用户截图中列表仅露出约两行，空预览与已完成任务仍占据主要空间。用户选择方案 2：默认专注列表，点击文件后再打开覆盖式查看器，兼顾手机、Pad 和电脑。

## Decision

本篇默认只读、显式编辑和手动占满的决定由[直接编辑与精简文件窗口](2026-10-10-direct-file-editor.md)部分取代；显式选择模式及选择入口由[统一直接勾选与稳定状态栏](../simplification/2026-10-10-unified-file-selection.md)部分取代。下述覆盖层生命周期、列表优先及权限边界仍保留。

- 默认仅显示紧凑标题、状态、路径、操作和文件列表。目录入口管理由[固定文件系统根](../simplification/2026-10-12-fixed-filesystem-root.md)删除；任务详情仍按需打开侧面板，窄屏覆盖可用区域，不固定占位。任务入口保留运行/异常摘要，不因新任务自动展开，不因收起而停止监听、取消任务或隐藏历史记录。
- 点击文件立即打开查看器并呈现该次加载/失败状态；新文档默认只读。宽屏为留边大覆盖层，可切换占满；面板宽度不超过 820 CSS px 或高度不超过 540 CSS px 时铺满。断点基于容器而非设备名，Pad 分屏也能切换。手机主操作栏在底部，其他尺寸在列表上方。
- 返回列表仅隐藏查看器，不关闭文档或保存/丢弃草稿。列表和编辑器保留挂载，收起/占满/响应式变化不重建同一编辑器，不清空列表滚动、勾选或草稿。已打开文档可恢复与切换；关闭最后一份文档回到列表，关闭脏文档沿用保存/放弃/取消确认。
- 文件读取用原有 generation 隔离竞态，异步完成只更新文档/加载状态，不打开界面，因此返回后迟到响应不会重开。失败遮蔽上一文档而不销毁其编辑器；不能预览的文件保留失败原因，并提供明确绑定该文件的下载入口，不借用勾选集合猜测目标。
- 操作分为新建、上传、选择及更多。显式选择模式点可操作行只切换勾选，完成模式清空勾选；普通点文件仍不改变勾选。批量动作、路径复制、忙碌/保存/权限禁用及服务端确认保持原契约，完整路径继续局部横向滚动。
- [覆盖层](../../../../src/client/overlay.tsx)保持内容挂载，隐藏区域不可交互；背景 inert，层有标题、Tab 循环和恢复焦点，返回聚焦不滚动列表。仅打开期间安装 document bubble 键盘监听，等子组件处理后再处理 Escape；suspended 子确认期间不抢焦点、不消费其 Escape，输入法组合与重复 Escape 不误关闭。
- 原生 details 承载动作分组，同工具栏分组互斥，支持外点关闭；普通按钮不冒充 menu。动作关闭后只把仍留在隐藏按钮上的焦点交回 summary，不抢手动复制文本自行获得的焦点。
- 仅调整 Client、对应测试和说明；不改变 Host、HTTP/存储协议，不新增搜索、富媒体预览、拖动多窗口或发布流程。

## Existing decision audit

实施前检索唯一命中为[路径复制](2026-10-09-copy-paths.md)，部分重叠：保留预览与勾选隔离、原始路径复制、只读降级及失败手动复制；仅改变所选路径按钮的操作区域，两篇互链，无须归档。[SPEC](../../../../SPEC.md) R5 草稿、R7 删除、R13 历史、R20 面包屑及 R21 编辑器生命周期仍有效；R23 记录本次布局和可见性规则。旧固定区域布局被替换，不维护另一套手机业务实现。

## Alternatives considered

- 全端页面切换：最简单一致，适合长时间编辑；但用户选择更贴近日常文件查看的覆盖式界面，需要背景列表的位置感。
- 宽屏按需两栏：连续查看多个文件的效率更高；但仍分割列表与内容，偏向编辑工作台，不是本次选择。
- 仅折叠旧布局：改动小且熟悉；仍留下复杂嵌套滚动与区域争抢，不能解决用户的主要问题。
- 普通确认 Modal 承载编辑器：能直接复用现成焦点逻辑；已安装 primitive 关闭时 return null，卸载内容，不能保留同一编辑器的撤销历史，因此不用于常驻查看器。删除、冲突和关闭等确认仍复用原 primitive。

## Consequences

文件列表不再被空预览或历史任务挤压，阅读/编辑按需占用空间，三端共享同一状态和权限逻辑。代价是低频操作多一次展开，覆盖查看时不能直接操作背景列表，需要返回；若后续以持续多文件编辑为主，应重新评估按需两栏，而不是在此添加浮动多窗口。

保留挂载意味着隐藏的已打开编辑器仍占用内存，与原文档缓存生命周期一致；关闭文档和卸载继续释放资源。布局实现承担了保留挂载的焦点管理责任，子确认/菜单必须维护 suspended 和事件归属规则。

真实系统软键盘与物理 IME 仍需真机复核。独立浏览器夹具不代表某个运行中 GUI 已安装/激活；仓库不记录特定实例部署结果，升级需按安装流程重新加载包并刷新。构建、功能测试和 GUI 激活必须分别报告。
