# Agent Note: 直接编辑与精简文件窗口

Status: implemented

## Problem

用户桌面和手机截图中，同一文件名同时出现在标题及单项文档栏，具体路径与编辑/关闭又占独立一行。用户确认打开即可编辑，不保留显式编辑开关；关闭改用右上角 X。DSH 公开 Button 与 IconCloseOutlineRegular 可复用，全屏外扩图标存在但还原图标和整套窗口标题栏没有公开素材，用户决定删除最大化和还原及对应逻辑，不自绘补齐。

浏览器基线发现：390px 的编辑器 mount 裁切约 3125px 宽的编辑器，内部 scroller 的 clientWidth 与 scrollWidth 相等，scrollLeft 最大值为 0；桌面 1319px 也复现。长行撑开 flex 子项，外层隐藏溢出但内部没有滚动范围；white-space:pre 且未启用 CodeMirror lineWrapping 使手机长行无法完整阅读。

## Decision

单文件标题和窗口 X 关闭当前文档的原决定由[文件标签与编辑窗口分离关闭范围](../bug-fix/2026-10-13-editor-close-scopes.md)部分取代：单文件也有独立标签 X，窗口 X 只退出编辑界面并保留草稿。下述直接可写、原生换行、公开宿主组件及保留挂载的决定继续有效；原关闭设计保留在本篇以解释演变，不作为当前关闭契约。

- 可写、未失效的文档打开即能编辑；删除 OpenDocument.editing、显式编辑按钮与 CodeEditor.mode 输入，仅从 canWrite 派生可写性。data-fm-code-mode 的 edit/preview 只描述权限派生状态，不是用户切换模式。打开本身不变脏、不自动保存，不自动聚焦输入框。
- 删除 viewerExpanded、Overlay.expanded、最大化/还原控件、翻译与专属样式。保留原容器响应式铺满规则：宽度不超过 820px 或高度不超过 540px 时铺满，更大窗口固定留边；不引入替代窗口状态。
- 顶部一条标题/文档导航行：返回列表、单文件名或多文档可滚动切换区域、保存、最右侧 X。单文档不重复展示标签；多文档导航代替标题。具体路径不占可见行，仅在必要的无障碍名称/提示保留，用于区分同名文档。
- X 复用 DSH 的 Button.icon + IconCloseOutlineRegular，关闭当前文档沿用保存/放弃/取消；保存中不可关闭。加载/失败期间 X 只退出该次查看并使迟到响应失效，不关闭被遮蔽旧文档。返回列表/Escape/背景点击继续仅隐藏，保留草稿与编辑器。
- 手机按实际文件面板宽度不超过 600px 使用 CodeMirror 原生 lineWrapping，宽屏不换行并允许内部横向滚动。编辑器 flex 子项 min-width:0，样式不再强制覆盖 CodeMirror 的 white-space。软换行不改变实际文本、BOM或换行元数据。
- ResizeObserver 观察面板内容宽度，重配原 view 的 wrapping Compartment，不丢选区/撤销/草稿；零宽隐藏通知不改变既有决策，无 ResizeObserver 时初测与 window resize 降级。销毁后不响应排队回调。降级 textarea 使用原生 wrap，readonly pre 同步窄屏换行。
- 仅复用公开的 DSH 按钮与关闭图标；局部布局约束用于组合现有组件和修复滚动，不自绘窗口素材、不换成会卸载编辑器的 Modal。不修改 Host、HTTP、持久化或依赖。

## Existing decision audit

- [响应式查看器](2026-10-09-responsive-file-viewer.md)：部分取代默认只读、显式编辑及可手动占满的决定；隐藏而非卸载、竞态、子层键盘归属和列表优先仍成立，因此保留并互链，不归档。
- [路径复制](2026-10-09-copy-paths.md)：不改变目录路径复制和勾选路径复制，原契约继续有效；本次仅删除文件窗口的可见路径行。

## Alternatives considered

- 默认只读加编辑入口：能降低误触输入，但增加一次操作和独立模式状态，用户明确要求打开直接编辑；误操作保护仍由显式保存、版本校验及脏文档关闭确认承担。
- 保留最大化并复用同一个图标表示还原：无需自绘且可保持放大能力，但状态含义不清晰，用户选择直接删除两者及逻辑。
- 复用 DSH Modal 整体：标题和 X 现成且主题统一，但关闭时卸载内容，不满足返回保留同一编辑器撤销历史，因此仅复用 Button 与公开关闭图标。
- 仅让整个页面横滑：能快速看到长行，但带走窗口控件和路径导航，手机难以操作；滚动归编辑器，窄屏优先原生软换行。

## Testing

- 类型检查、构建、产物语法与笔记校验通过；完整套件以 UID/GID 1000 运行，800/800，0 失败、0 跳过。覆盖直接编辑、权限/失效、BOM/换行、冲突、保存期间继续输入、关闭确认、晚到响应、降级、语法高亮预算、IME和生命周期。
- 原编辑模式测试迁移为可写性门禁，不删只读或内容保证。新增四项响应式 DOM 测试覆盖 600px 边界、零宽隐藏、观察器清理、无 ResizeObserver 与降级控件；jsdom 不作为几何证明。
- 初次完整测试暴露文件替换后 3 个测试文件权限为 600、独立 verify-client 夹具缺公开图标 stub，以及旧 i18n 测试仍要求 edit 文案。恢复 644、补齐独立边界并断言删除的动作标签不存在后，全套通过；没有修改生产行为来迁就测试。
- 同一构建与真实宿主组件的 Chromium 夹具共 15 条记录通过，包括 11 组尺寸/主题与状态场景。390px 原生软换行后 ASCII/CJK 行末可达，模型不变；1319px scroller 实测 clientWidth 1269、scrollWidth 大于 clientWidth，能内部横滑到行末。dirty 下缩放/返回保持 node、选区、撤销和滚动；长名/多文档不挤出保存/X。
- Lead 复核最终普通代码及明暗截图。最初代码区中文缺字体，属于夹具的等宽字体回退问题；仅在忽略的验证 artifact 加入已加载完整中文字体，CDP 实际字体记录证明 CJK 使用 NotoSansCJKsc-Regular，再次通过同一矩阵，不向产品添加字体依赖。

## Consequences

窗口去掉两套独立模式状态和重复信息，手机为代码留出更多空间，默认可写但写盘仍需显式保存。代价是少了手动扩大桌面窗口的能力，直接编辑更依赖现有脏状态及关闭确认；用户已明确选择这些行为。

软换行是视觉行变化，不是格式化。多文档导航在窄屏局部横滑，窗口按钮保持可达。保留挂载继续占用已打开编辑器内存，与原缓存生命周期一致。

物理手机软键盘/IME仍未验证；浏览器夹具不是已认证 live GUI 的激活证明。仓库不记录特定实例安装结果；安装、运行中模块激活和测试分别报告。
