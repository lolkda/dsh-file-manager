# Agent Note: 失效根入口的显式恢复与同路径去重

Status: implemented
Archived: 2026-10-12

## Problem

Docker overlay 根目录的设备号或 inode 可以在容器重建/重新挂载后变化，而持久化入口仍保留旧身份。现场保存过三个同路径 `/`、不同 identity 的入口，已安装版本对失效入口返回 ROOT_CHANGED。客户端默认选择保存位置或第一个入口，不检查可用性；重新添加不同身份的同路径又创建一条入口，导致旧错误反复出现。用户批准兼容性修复，并要求 Agent Team 实现后由 Lead review。

## Decision

普通恢复结果与状态检查错误的展示由[会话内通知中心](../../implemented/feature/2026-10-12-notification-center.md)部分接管；根状态徽标、显式恢复确认和下述身份/重试/旧引用隔离规则不变。清除通知不改变任何授权。

- 保留 R2：每次文件 I/O 继续验证目录身份与规范路径，不自动接受新目录，不改磁盘内容，不重置存储或任务历史。
- 保留现有 RootDescriptor、bootstrap 和 roots.list 的返回形状及 V1 存储。新增只读 `roots.status`，返回 `{ rootId, status: 'available' | 'changed' | 'unavailable', currentIdentity?: string }[]`；只有安全打开且规范路径一致时暴露 currentIdentity，不持久化瞬时状态。逐项核验、释放句柄，一项不可用不阻断其他入口。
- 新增 `roots.reauthorize`：`{ rootId, expectedIdentity, confirmed, requestId }`。只有显式确认且当前安全打开目录的身份等于确认时的 expectedIdentity 才执行；仍拒绝路径替换、链接和确认后再次变化。缺确认拒绝；只读降级拒绝；沿用 mutation ledger 幂等性。
- 恢复结果 `{ root, removedRootIds }`。只处理所选入口的完全相同规范路径；复用同路径当前有效授权（如已有），否则创建全新 ID。原子持久化后才更新内存，并撤销该路径其余旧 ID，不改其他路径。旧请求、草稿、删除计划、任务检查点不自动改绑新 ID；未完成操作依赖已有根撤销检查失败。
- `roots.add` 对已有相同路径但全部身份失效的情况返回 ROOT_CHANGED，提示进入显式恢复，不再累积重复入口；相同身份的重复添加继续幂等复用。
- 客户端启动先核验状态，优先保存位置对应的有效入口，其次第一个有效入口；全部无效时打开目录位置而不尝试失效根。列表标记失效/不可用，明确提供重新授权与刷新状态。移除后的回退也只选择有效入口。
- 重新授权在独立确认对话框展示目标路径与“不删除文件、旧任务不迁移”的语义，取消无副作用；确认中禁止重入，迟到响应不能复活已关闭/卸载界面。成功只把撤销 ID 对应文档标记失效并保留草稿，清除指向旧 ID 的位置/选择/剪贴板，不迁移任务。仍有效且未撤销的当前位置与勾选保留；旧 ID 被撤销时，即使规范路径相同也不得把旧子目录或勾选套到新 ID。
- 网络结果不确定（TRANSPORT/CANCELLED）允许同 requestId、同 expectedIdentity 重试；服务端明确失败被 ledger 缓存，须重新核验并经新 requestId 再确认。恢复已成功而后续刷新失败时，只报告刷新失败，不撤销或误报既成恢复结果。
- confirmed mutation 的草稿/剪贴板/共享位置撤权效果在视图卸载后仍落地；React 更新、后续网络与导航受 alive、attempt 和 lifetime 门禁保护。状态查询失败保留上次快照并显示错误；仅旧 Host 明确 INVALID_REQUEST（不支持新增 operation）时回退旧导航，不能把 malformed success 当成不支持。

## Alternatives considered

- 按路径自动接受新 inode：容器重建后无需操作，最省交互；但把原授权无声交给新目录，破坏既有 R2，用户已选择保留身份校验。
- 继续让用户手动移除再添加：不需要协议增量，也保留明确授权；但多条同名旧入口无法区分，移除后还可能回退到另一失效入口，正是本次复发的体验缺陷。
- 在 bootstrap/roots.list 的每个 RootDescriptor 增加状态：少一次网络请求；但现有严格 DTO 校验与旧消费者可能拒绝新增字段，因此采用独立只读 operation，不把运行态写入授权存储。

## Review and verification

Lead 逐文件检查相对修复前基线的增量，关闭这些问题：确认到落盘期间持有目录句柄；保留有效根对象引用；状态快照避免遍历活 Map；状态索引防原型键并核验身份格式；区分 ledger 的确定失败与网络未知；恢复成功不被后续刷新失败误报；撤权效果跨视图保留而迟到 UI 响应受 lifetime/attempt/generation 门禁；有效位置不被恢复其他入口打断，撤销位置不向新 ID 继承子目录或勾选；无可用移除回退重新打开位置面板。

实际验证（最终共享 dist，以普通 UID/GID 1000 运行，避免 root 绕过权限夹具）：

- `npm run check`：类型检查、Host/Client 构建、20 个产物语法检查通过。
- `npm test`：860/860 通过，0 失败、0 取消、0 跳过，比修复前既有记录增加 46 个用例。
- Host 四文件针对性 83/83；完整 Host 侧 407/407。Client 恢复专用 27/27，客户端及接口验证 285/285。这些是同一完整套件的子集，不累计充当额外测试数。
- 回归覆盖：逐根只读状态、启动避开失效根、全部失效仍同步任务、添加不增长重复入口、确认/取消、确认后目录变化、持久化失败、幂等重放、只读拒绝、同路径有效 ID 复用、其他路径不变、旧 ID 暂存发布拒绝、草稿/剪贴板隔离、卸载后域效果、恢复后刷新失败及保留有效子目录/勾选。保留位置的子目录在窗口期消失仅对 NOT_FOUND 回退同根；根级 ROOT_CHANGED/ROOT_UNAVAILABLE 不得再尝试根目录，两个分支均以真实文件系统变化验证。
- 测试 fixture 只补新增状态查询与正确的 follow-up 等待：旧 Host 用明确 INVALID_REQUEST 表达不支持，不能用非法成功响应 `{}` 冒充；原取消错误断言保留。

## Consequences

收益是失效入口可辨识、不再堆叠、恢复由一次明确确认完成；有效授权和既有任务历史不需要迁移。状态检查和操作之间仍存在时间窗，因此显示状态不能代替每次 I/O 校验；expectedIdentity 只绑定这次明确确认的根身份。新增检查带来一次只读请求及每根一次打开/关闭开销。合法的容器重建仍需用户确认一次，不承诺永久免确认。

真实 GUI 未完成本轮验收：Chrome DevTools 无可用浏览器，现有 GUI 匿名访问返回 401；未查找凭据，不把组件/HTTP fixture 结果冒充已认证页面或窄屏像素验收。代码构建不等于运行实例已更新，本次不自动重启 DSH、不改线上授权存储。

当前工作区有先前未提交变更；本次基线保存在 artifacts/root-recovery-2026-10-12/baseline，交付报告按该基线计算增删行数，不把已有改动计成本次工作。原始基线与测试日志是本地证据，不随包发布。
