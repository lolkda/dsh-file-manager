## 2. 目标与范围

### 背景

用户反馈永久删除含大量文件的目录时长时间等待。排查时已安装插件与修复前工作区构建的删除模块 SHA-256 一致；旧实现删除每个叶子前均递归核验父目录，最终重新从根打开所选路径，并发叶子重复执行相同父路径核验。修复仅合并在途核验。浏览器调试连接不可用，GUI HTTP 返回 401，未取得已认证页面运行证据；工作区修复不等于运行实例已激活。

### 目标

减少大量文件删除的重复路径 I/O，以真实隔离目录的修复前后测量和确定性回归验证，保留原有删除及安全语义。

### 非目标

不引入回收站、后台删除任务、进度协议或界面文案变化；不改变确认、TTL、去重、幂等及部分失败回执；不对任意磁盘和任意目录规模承诺固定耗时；不重启或替换当前 DSH 实例。

## 4. 行为要求与约束

### R-001：减少重复核验

- 参与者或触发方：确认永久删除的用户。
- 前置条件与输入：有效所选树删除计划，目录包含大量叶子。
- 必须满足的行为：相同目录的并发删除不为每个叶子重复执行相同的在途父链核验；仍对实际文件逐个删除，I/O 保持有界。
- 输出或状态变化：实际执行完成后才返回原有完成或部分失败回执。
- 边界与失败行为：等待全部已启动操作排空后返回并关闭描述符，不因失败提前返回。

### R-002：不得跨核验周期复用结果

- 参与者或触发方：目录删除器及外部文件变更。
- 前置条件与输入：根、祖先目录或叶子可能在删除期间改变。
- 必须满足的行为：保留根/父链核验、目录 O_NOFOLLOW 和身份检查、逐叶 unlink 前检查，以及硬链接版本保护；只能共享尚未完成的核验，不缓存已成功或失败的结果供后续周期使用。
- 输出或状态变化：遇到替换仍拒绝相关删除，实际部分删除事实如实报告。
- 边界与失败行为：共享核验失败传播到所有等待者；后续周期重新核验，不永久粘住错误。符号链接不跟随，兄弟目录不删除。

### 相关约束

- 既有 R7 要求单次执行遍历、原始名称、有限并发、变化目录批量同步、回执幂等，均保持。
- 已有工作区含大量未提交修改，本次仅修改删除器、新增回归/基准及本规格，不回退其他工作。

## 5. 关键决定

### D-001：仅合并在途核验

- 状态：委托范围内决定。
- 结论：在删除器各级目录核验闭包内共享一个在途 Promise；完成或失败即清除，后续调用发起新核验。共享状态仅存活于当前树遍历。
- 理由：同批叶子面对同一父链，重复打开和检查增加系统调用；合并在途操作无需修改外部协议或降低逐叶检查。
- 考虑过的备选：直接使用递归 fs.rm；长期缓存父链检查；异步提交后立即报告成功。
- 未采用原因：分别损害描述符相对安全边界、接受过期身份，或虚报删除完成；不符合现有契约。
- 影响范围：R-001、R-002、AC-001 至 AC-004。

## 6. 验收标准

### AC-001：并发核验合并与性能测量

- 对应规则：R-001。
- 前置条件：真实目录包含跨多个并发批次的文件，另有深路径夹具。
- 操作或输入：执行 prepare/commit，记录根目录重新打开次数；对相同结构的独立干净夹具测量旧版和新版。
- 预期结果：并发叶子共享在途核验，根重新打开次数显著低于叶子数；树确实删除，未选兄弟保留；记录实际耗时而非设置脆弱绝对秒数阈值。
- 验证状态：通过。
- 验证证据：[新增回归](../../tests/delete-performance.test.mjs)覆盖同级文件、深父路径、深子树。修复前 256 个叶子需 263 次根打开，性能断言失败；修复后同级和深父路径均为 39 次，深子树为 63 次，峰值 unlink 并发保持 8。12,000 文件 × 2 种父路径深度 × 新旧各 3 次均完成真实删除，兄弟保留；数据见下表及[原始测量](../../artifacts/permanent-delete-performance/benchmark-results.json)。

### AC-002：后续核验检测父路径替换

- 对应规则：R-002。
- 前置条件：第一批叶子已完成，下一批前将所选树的祖先替换。
- 操作或输入：继续提交删除。
- 预期结果：返回部分失败，后续批次不删除移走树的剩余文件或替换树内容；无描述符泄漏。
- 验证状态：通过。
- 验证证据：[新增回归](../../tests/delete-performance.test.mjs)的 root、ancestor、selected-directory 三种交换通过；仅第一批 8 个文件被移除，下一批 8 个与替换内容保留，错误分别为 ROOT_CHANGED/PATH_CHANGED，描述符数量恢复。

### AC-003：失败传播与无错误缓存

- 对应规则：R-001、R-002。
- 前置条件：并发核验期间注入一次可控失败，随后恢复。
- 操作或输入：多个叶子等待同一核验，继续处理下一批。
- 预期结果：失败传播给所有等待者；后续批次重新核验；最终回执保留部分失败，等待者与描述符全部收尾。
- 验证状态：通过。
- 验证证据：[新增回归](../../tests/delete-performance.test.mjs)通过可控 Promise 门注入一次 EACCES；第一批 8 个等待者均不删除，后续批次重新核验并删除，最终 partial/contentsChanged=true，描述符数量恢复。旧版仅一个等待者失败，不能满足共享失败断言。

### AC-004：现有删除保护保持

- 对应规则：R-001、R-002。
- 前置条件：现有真实文件系统、HTTP 和 Client 回归夹具。
- 操作或输入：类型检查、构建，执行全部适用回归；权限用例使用普通用户运行。
- 预期结果：确认、scope、TTL、幂等、链接及竞态保护、部分失败、排空和草稿行为继续通过；不得把未执行的真实 GUI 验收称为通过。
- 验证状态：通过。
- 验证证据：`npm run check`、`npm run verify-notes` 通过；UID/GID 1000 执行完整 `npm test` 为 927/927，0 失败、0 跳过，含 7 项新增回归。早期 root 专项运行的 5 个权限跳过已由普通用户完整测试补齐。[完整验证日志](../../artifacts/permanent-delete-performance/validation.txt)。已认证 GUI 和运行中实例激活未验证，不计作本次源码验收通过。

### 测量与重放

同一 Linux Host、Node v24.21.0、每轮新建 12,000 空文件夹具；只统计提交删除，不含夹具创建，测量时不并行运行全量测试。三轮中位数如下；这是本机样本，不是任意磁盘性能承诺。

| 目标父路径深度 | 修复前提交耗时 | 修复后提交耗时 | 耗时下降 | 根目录打开次数（前 → 后） |
|---|---:|---:|---:|---:|
| 0 | 2197.84 ms | 1160.23 ms | 47.2% | 12007 → 1507 |
| 8 | 6058.05 ms | 2540.13 ms | 58.1% | 12007 → 1507–1508 |

[基准脚本](../../scripts/benchmark-delete.mjs)只操作自建临时目录，最多 100,000 文件、10 轮；参数为 manager 模块、文件数、重复次数。旧模块需与[测量数据](../../artifacts/permanent-delete-performance/benchmark-results.json)的 SHA-256 对齐，安装目录将来升级后不能冒充旧版基线。

## 7. 未决问题与假设

### Q-001：实际目录规模与磁盘成本

- 类型：暂用假设。
- 内容：重复父路径 I/O 是当前可直接复现并优化的瓶颈；用户未指定具体问题目录，磁盘 unlink/fsync 成本和目录结构仍可能影响实际收益。
- 影响范围：性能结论不外推为所有文件系统固定倍数。
- 是否阻塞：否，使用隔离大量文件夹具验证，不触碰用户数据。
- 决定或验证方式：记录测量环境、文件数量与路径结构；如实际仍慢，后续针对具体目录进一步采样。

### Q-002：运行实例激活

- 类型：未决问题。
- 内容：本次工作区构建不等于正在运行的插件已加载修复；已认证 GUI 调试不可用。
- 影响范围：部署与端到端页面验收。
- 是否阻塞：否，不阻塞源码修复和隔离验证；阻塞声称当前 GUI 已生效。
- 决定或验证方式：单独报告未部署，安装/重启由用户另行确认。
