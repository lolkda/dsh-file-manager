## 2. 目标与范围

### 背景

文件列表当前对每个文件显示 `entry.size.toLocaleString()` 加“字节”，上传确认弹窗也以同样方式显示所选文件的总大小。用户要求不再显示原始字节数，改为更紧凑的 K/M 单位；原话“大于 1K 就显示 M”按字面会造成 `1,025 字节 → 0.001M`，经确认改为常见的连续单位阶梯。

### 目标

- 文件列表与上传确认汇总使用同一套二进制 K/M/G 文件大小格式。
- 不显示 `B`、`bytes` 或“字节”等单位文字。

### 非目标

- 不改变协议、Host 或任何原始大小字段；文件大小仍以字节数传输和计算。
- 不改变任务卡片进度条、任务计量、排序、上传限额或文件系统行为。
- 不为目录显示推算大小，不新增单位设置或本地化单位名称。

## 4. 行为要求与约束

### R-001：统一格式化入口

- 参与者或触发方：文件列表渲染普通文件大小，或上传确认弹窗渲染所选文件总大小时。
- 前置条件与输入：大小为非负的安全整数，单位为字节。
- 必须满足的行为：两处都必须调用同一个文件大小格式化函数；不得直接把原始字节数拼接为可见文字。
- 输出或状态变化：输出紧凑的“数值 + 单位”文本，单位只使用 `K`、`M`、`G`，数值与单位之间不添加空格。
- 边界与失败行为：0 字节必须显示 `0K`；非空但按一位小数格式化后小于 `0.1K` 的文件必须显示 `0.1K`，不得显示 `0K`。

### R-002：二进制单位阶梯与精度

- 参与者或触发方：文件大小格式化函数。
- 前置条件与输入：非负字节数。
- 必须满足的行为：
  - 以 1024 为换算基数：小于 `1 MiB` 使用 K，`1 MiB` 及以上且小于 `1 GiB` 使用 M，`1 GiB` 及以上使用 G。
  - 保留一位小数并四舍五入，末尾 `.0` 必须省略，例如 `1.5K`、`1K`、`2M`。
  - 四舍五入后若 K 数值达到 1024，则改用 M；若 M 数值达到 1024，则改用 G，避免显示 `1024K` 或 `1024M`。
- 输出或状态变化：`1,024 字节 → 1K`、`1,048,576 字节 → 1M`、`1,073,741,824 字节 → 1G`、`2,147,483,648 字节 → 2G`。
- 边界与失败行为：不得因格式化舍入改变底层大小、排序或限额判断；显示近似值不参与任何业务计算。

### R-003：文件列表

- 参与者或触发方：目录列表渲染文件条目。
- 前置条件与输入：条目类型为普通文件，且具有 Host 返回的字节大小。
- 必须满足的行为：文件行的大小文字必须使用 R-001/R-002 的格式；目录行仍不显示大小。
- 输出或状态变化：仅替换大小文字，文件名、选中、打开、禁用与无障碍语义不变。
- 边界与失败行为：极长文件名、不可寻址条目和特殊文件类型的既有处理不变。

### R-004：上传确认汇总

- 参与者或触发方：用户选择文件或目录后打开上传确认弹窗。
- 前置条件与输入：上传计划包含一组所选来源及其文件大小。
- 必须满足的行为：弹窗顶部的“N 项 · 总大小”必须使用 R-001/R-002 的格式，不得显示原始字节总数。
- 输出或状态变化：仅替换总大小文字；冲突策略、重名、忙碌、取消和开始上传行为不变。
- 边界与失败行为：目录和空文件按现有计划大小求和；总大小为 0 时显示 `0K`。

### 相关约束

- 任务卡片继续只显示完成项数、状态和进度条，不新增大小文字；这沿用 0.5.4 的界面收敛。
- 大小字段、协议 DTO、HTTP 入口、存储格式和权限模型均不改变。
- 不在浏览器端重新计算文件内容或读取文件；格式化只使用已有元数据。

## 5. 关键决定

### D-001：采用二进制 K/M/G 连续阶梯

- 状态：已确认
- 结论：使用 1024 基数，1 MiB 以下用 K，1 MiB 至 1 GiB 以下用 M，1 GiB 及以上用 G。
- 理由：符合常见文件管理器习惯，避免按字面“超过 1K 转 M”产生 `0.001M`，也避免大文件显示为 `2048M`。
- 考虑过的备选：仅 K/M 两级；严格按字面在 1K 处切换到 M。
- 未采用原因：前者会让 2 GiB 显示为 `2048M`；后者会产生不可读的极小 M 值。
- 影响范围：R-001、R-002、R-003、R-004。

### D-002：一位小数并保护极小非空文件

- 状态：已确认
- 结论：保留一位小数、四舍五入并去掉末尾 `.0`；0 字节显示 `0K`，非空但不足 `0.1K` 显示 `0.1K`。
- 理由：兼顾紧凑与可读性，避免用户把有内容的文件误认为空文件。
- 考虑过的备选：两位小数；整数四舍五入。
- 未采用原因：两位小数文字更长，整数会丢失较多精度。
- 影响范围：R-001、R-002。

### D-003：两处可见文字同时调整

- 状态：已确认
- 结论：文件列表和上传确认汇总统一使用新格式。
- 理由：避免同一页面出现两套大小表达。
- 考虑过的备选：仅修改文件列表。
- 未采用原因：上传汇总仍显示字节会与列表不一致。
- 影响范围：R-003、R-004。
